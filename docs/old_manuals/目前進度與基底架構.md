## 一句話現況

本機已串通一條路：**上架（圖＋公版）→ FashionCLIP 推薦／穿搭補齊 → 試穿（M2→M3→M4）→ 瀏覽器載入結果 GLB**。

- **FashionCLIP**：有裝 `requirements-fashionclip.txt` 時走真模型；未安裝或 pytest 時走 mock 向量（HTTP 仍通，分數不能當語意正確）。
- **M2～M4**：本機有 SMPL-X `.npz` 且非 pytest 時走出人體／衣服／合成 GLB；pytest、缺權重或例外時退回示範 GLB，接口仍成功。
- **M4 名稱像物理**，實作是幾何蒙皮／姿勢貼合，不是布料碰撞與重力。畫布上模型**沒有商品花色是預期**（UV 未做）。

產品站 `web/`（`/`）與開發頁 `web_test/`（`/dev`）都已接同一套 REST；產品站尚未當正式定稿。

## 基底架構

```
瀏覽器
  ├── /          產品站  web/          （檢索、穿搭、試穿、商家上架）
  └── /dev       開發頁  web_test/     （聯測／Demo 建議走這裡）
        │  REST + 靜態 GLB / 商品圖
        ▼
Flask (localhost:5000)
  ├── module1_pipeline     上架、列表、詳情、推薦、穿搭補齊
  ├── module_integration   試穿 orchestrator（依序 M2→M3→M4）
  ├── adapters/            隊友模組適配層（可整檔替換實作）
  ├── geometry_physics/    Chi 幾何引擎、公版 OBJ、SMPL-X 權重
  └── outfit_transformer/  穿搭補齊模型
        │
        ├── MySQL `3d_tryon`     products / body_profiles / tryon_sessions
        ├── FAISS                data/faiss_index/product.index
        └── 檔案                 data/uploads/  data/outputs/  data/samples/
```

資料流：

1. **上架**：圖片 + 名稱 → FashionCLIP 向量 → FAISS；商品列寫入 MySQL；圖存 `data/uploads/products/`。可帶 `garment_template_id`、尺寸表（給試穿 M3，不影響 CLIP）。
2. **推薦**：文字（或伺服器本機圖路徑）編碼 → FAISS 搜最近鄰 → 回商品列表。
3. **穿搭補齊**：已選 `product_ids` + 目標分類 → OutfitTransformer → 補齊商品，可再拿去試穿。
4. **試穿（同步 v1）**：身材參數存 `body_profiles` → M2 出身體 GLB → M3 出衣服 GLB → M4 出結果 GLB → `tryon_sessions` 記路徑。回應可帶 `elapsed_seconds`。

Celery／Redis **還沒接**。真實 SMPL-X 第一次擬合常約 30～60 秒，同體型之後可走快取；若之後常超過約 30 秒，再改非同步。`GET /api/tryon/status/{id}` 已預留。

## Adapter 契約（請對齊，勿改函式名）

| 檔案 | 函式 | 輸入 | 輸出 |
|------|------|------|------|
| `fashionclip_adapter.py` | `encode(image_path, text)` | 路徑與／或文字 | `np.ndarray`，形狀 `(512,)`，`float32` |
| `body_generator.py` | `generate(height_cm, chest_cm, waist_cm, hip_cm, output_name)` | 公分、輸出檔名前綴 | `{ "glb_path": str }`（可另寫 sidecar） |
| `garment_processor.py` | `prepare(product_id, size)` | 商品 id、尺寸字串 | `{ "glb_path": str }` |
| `physics_simulator.py` | `run(body_glb, garment_glb, output_name)` | 兩個 GLB 路徑 | `{ "glb_path": str }` |

公版對照（上架 `garment_template_id` → M3 OBJ）見 `garment_processor.GARMENT_TEMPLATES`（如 `tshirt_base.glb`、`pants_base.glb`）。

向量維度預設 512，可用 `.env` 的 `FAISS_VECTOR_DIM` 改。若你改維度或換成真 CLIP，要清掉舊的 `product.index` 並重新上架／seed。

pytest 會設環境讓 M2～M4 與 CLIP 走 stub／mock，**不要用 pytest 結果判斷真實人體或推薦語意**。

## 本機怎麼開（後端）

環境細節見 [`環境設定手冊.md`]。最短路徑：

```powershell
cd "c:\Users\User\EEproject\3Dclothes_project"
.venv\Scripts\Activate.ps1
copy .env.example .env          # 第一次
python -m database.init_db      # 建表（需 XAMPP MySQL、庫名 3d_tryon）
python -m database.seed         # 灌測試商品
flask --app app run
```

可選：`pip install -r requirements-fashionclip.txt` 才有真 CLIP。  
SMPL-X 權重放 `geometry_physics/assets/smplx/`（授權檔，僅限非商用課程）。

驗證：

- 開發頁：`http://127.0.0.1:5000/dev`
- 產品站：`http://127.0.0.1:5000/`
- `GET http://127.0.0.1:5000/api/health`
- 列表：`GET /api/products`
- 推薦：`POST /api/recommend`，body `{"query_text": "白色短袖", "top_k": 5}`
- 試穿：`POST /api/tryon/simulate`，`product_id` 用 seed／上架後的 id

種子商品為原創測試資料。**不要爬品牌官網當資料庫。**

自動測試（不需 MySQL、不載真模型）：

```powershell

```

## 前端現在可以接的行為

1. **列表／詳情**：`GET /api/products`、`GET /api/products/{id}`。
2. **搜尋**：`POST /api/recommend`（真 CLIP 才有語意；mock 時流程通但排序不可信）。圖搜仍要伺服器本機路徑，不能直接丟瀏覽器檔案。
3. **穿搭**：`POST /api/outfit/complete`（`product_ids` + `target_category`）。
4. **上架**：`POST /api/products/upload`，記得帶 `garment_template_id`，試穿 M3 才會用對公版。
5. **試穿**：送身材四圍 + `product_id` + `size` → 拿 `result_glb_url` → Three.js 載入 `/static/outputs/{id}.glb`。第一次真 SMPL-X 可能要等數十秒。
6. **CORS**：產品站與開發頁由 Flask 同源提供，不必另開 5173。若前端獨立開在別的 origin，改 `.env` 的 `CORS_ORIGINS`。

產品站頁面：首頁、服飾檢索、穿搭補齊、3D 試穿、商家上架。Demo 口述建議固定走 `/dev`：搜一句話 → 點商品 → 試穿轉一圈。
