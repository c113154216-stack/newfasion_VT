# 🧵 縫合程式（sew.py）｜筆記

> 💡 **一句話**：GarmentCode 只會把版片「擺」在身體周圍，不會把它們縫起來；`sew.py` 把每條邊拉回版片上的原始長度、同時不讓布穿進身體，得到一件縫好、套在身上的衣服。
> 💻 程式：`tools/chatgarment/sew.py`
> 📅 2026-10-05 寫好、2026-10-17 加入限制拉長／彎曲剛度／重力

---

## 1️⃣ 縫合在整個流程的位置

```
照片 → AI 判斷款式 → GarmentCode 打版 → 版片擺在身體周圍（box mesh） → 【縫合】 → 縫好的衣服 → 交給物理模擬
```

- **縫合不是物理模擬**：沒有重力、摩擦、時間、動作。它只做一件事：把版片「拉合」成一件衣服，停在身體外側
- 縫好的衣服是紀泓宇物理模擬的**起始狀態**；之後衣服怎麼垂、怎麼跟著人動，是物理那邊的事

---

## 2️⃣ 輸入：box mesh 長什麼樣

GarmentCode 打版後，會輸出一個 **box mesh**（`*_boxmesh.obj`）：

- 每片版片（前片、後片、袖子）是一片**平的網格**，擺在身體周圍：前片平放在胸前、後片在背後、袖子往兩邊伸
- **縫線兩側的頂點已經合併成同一個點**。例如前片和後片的側縫，原本是兩條邊，現在共用同一排頂點
- 但前後片之間隔著身體，所以縫線附近的三角形被拉成**細長的「橋」**（最長的邊可能 30～40 cm）

> 圖：`docs/images/garmentcode_tshirt_boxmesh.png`

另外還有一個檔案 **`*_orig_lens.pickle`**：記錄這些「橋」上的邊，**在 2D 版片上原本有多長**。其他沒被拉扯的邊，現在的長度就是原始長度。

所以縫合的任務很清楚：

```
① 每條邊回到原始長度   → 橋縮回來，前後片就被拉在一起
② 不能穿進身體         → 布包在身體外面
```

---

## 3️⃣ 核心想法：每條邊是一根彈簧

想像整件衣服是用**很多根彈簧**接起來的網子：

- **每條邊 ＝ 一根彈簧**，它的「自然長度」就是版片上的原始長度
- 彈簧被拉長或壓短，就會想回到自然長度
- **身體 ＝ 一面牆**，布碰到就會被推出去

縫合就是：把所有彈簧放開，讓網子自己找到一個**大家都最舒服**的形狀。

用數學寫，就是找一組頂點位置，讓下面這個「不舒服的程度」（能量）最小：

```
能量 ＝  Σ  權重 × (邊的長度 − 原始長度)²            ← 彈簧
      ＋ 身體權重 × Σ (頂點 − 推到身體外的位置)²     ← 牆（只算碰到身體的點）
      ＋ 彎曲剛度 × Σ (頂點 − 鄰居的平均位置)²       ← 布的硬度（10-17 加）
      ＋ 重力 × Σ 頂點高度                           ← 往下的力（10-17 加，預設不開）
```

> **「平方」的意思**：差 1 cm 罰 1、差 2 cm 罰 4、差 3 cm 罰 9。差越多罰越重，所以會優先修正差最多的地方。

## 4️⃣ 怎麼找到最舒服的形狀：局部－全域交替法

直接解上面的能量很難（邊長牽涉到開根號）。所以拆成兩步，**反覆做 400 次**：

### 局部步：每條邊、每個點各自想「我理想的樣子」

**每條邊：** 保持**現在的方向**，但長度改成**原始長度**。

```
例：一條邊現在從 A 指向 B，長 10 cm，原始長度 6 cm
    → 理想的樣子：同一個方向、長 6 cm
```

程式（第 95～107 行）：

```python
d = A @ x                        # 每條邊現在的向量（xi − xj）
length = ‖d‖                     # 現在的長度
d *= rest / length               # 方向不變、長度縮放成原始長度 → 每條邊的「目標向量」
```

**每個碰到身體的點：** 理想位置是「推到身體表面外 0.5 cm」（`push_out`，第 40～46 行）：
- 用 **winding number** 判斷點在不在身體裡面
- 在裡面、或離表面不到 0.5 cm → 找身體上最近的點，沿著表面的法線方向往外推 0.5 cm

### 全域步：找一組位置，讓大家都盡量接近理想

每條邊都有自己的目標向量，但它們會互相衝突（一個頂點連著好幾條邊）。全域步就是找**一組折衷的位置**，讓所有邊都**盡量**接近目標。

這剛好可以寫成一個**線性方程組**，一次解出所有頂點的位置：

```
(Aᵀ W A ＋ 身體項 ＋ 彎曲項 ＋ anchor) x ＝ Aᵀ W d ＋ 身體目標 ＋ anchor × 原位置
```

其中 **A** 是一個「邊 × 頂點」的表格：每一列代表一條邊，在兩個端點的位置分別填 +1、−1，所以 `A x` 就是每條邊的向量（第 73～76 行）。

### 為什麼這樣做很快

- 左邊的矩陣**大部分時候不變**，可以先「分解」好（`factorized`），之後每次只要代入新的右邊就能秒解
- 2,000 個頂點的衣服，解一次只要幾毫秒

### 反覆做會發生什麼

```
第 1 輪：橋很長 → 目標說「縮短」 → 前後片往中間靠
第 2 輪：碰到身體了 → 身體把它推回去
……
第 400 輪：彈簧和身體達到平衡 → 縫好了
```

## 5️⃣ 幾個關鍵的小設計（每個都是踩過坑才加的）

| 設計 | 程式 | 為什麼需要 |
|---|---|---|
| **不能穿進身體是「軟限制」** | 第 110～116 行 | 一開始是每輪**硬把**頂點推出身體，結果硬推跟彈簧互相拉扯，**網格被扭壞**。改成把「推出去」也當成一根彈簧，跟其他邊一起求平衡 |
| **只有碰到身體的點才加身體項** | 第 114 行 `hit` | 沒碰到的點如果也加「目標＝自己」，會變成阻力、拖慢收斂。因為每輪碰到的點不同，所以這一項有開的時候，矩陣每輪要重新分解 |
| **每輪最多移動 1 cm**（`max_step`） | 第 123～126 行 | 一步移太遠，**後片會整片「跳過」身體**（從背後穿到胸前），碰撞根本來不及擋。限制每輪 1 cm，就不會穿隧 |
| **anchor（很小的權重 0.0001）** | 第 85、108 行 | 彈簧只管「邊多長」，不管「整件衣服在哪」。整件平移不會改變任何邊長，方程組就會有無限多解、解不出來。加一點點「拉回原位」就能固定位置，又不影響形狀 |
| **離身體 0.5 cm**（`margin`） | 第 40 行 | 剛好貼在表面上的點，數值誤差可能讓它一下在裡面、一下在外面；保留 0.5 cm 的空隙比較穩 |

## 6️⃣ 10-17 新增的選項：解決領口被撐大

### 問題：布被撐長了

舊設定縫出來的紅 T，**領口從版片的 71.6 cm 被撐到 99.1 cm（+38%）**；拉長超過 10% 的邊有 10.9%，最多拉長 94%。真的 T 恤穿在身上幾乎拉不長。

**為什麼？** 布碰到肩膀的斜面時，有兩種方式可以不穿模：

| 方式 | 布的長度 | 代價 |
|---|---|---|
| **A. 滑開**：換個位置包住肩膀 | 不變 | 要移動很多點 |
| **B. 撐開**：原地被撐長、繞過肩膀 | 變長 | 違反彈簧 |

程式會選「比較划算」的：
- **舊設定**：碰到身體的懲罰 10、彈簧被拉長的懲罰只有 1 → 撐開很便宜 → 選 **B**
- 撐得最嚴重的是**肩膀一圈**，衣服往下掛，領口被連帶撐大

### 選項 1：限制拉長（`stretch_limit`、`stretch_weight`、`stretch_mask`）

```
某條邊被拉長超過 stretch_limit（例如 2%） → 這條邊的權重從 1 改成 stretch_weight（例如 100）
```

程式（第 98～106 行）：每輪檢查哪些邊拉太長，把它們變硬。拉長變得很貴，程式就改選 **A 滑開**。

- `stretch_mask`：只對指定的邊限制（實驗用，例如只限制領口）
- 權重改了，矩陣就要重新分解

### 選項 2：彎曲剛度（`bend`）

**問題：** 限制拉長之後，布不能被撐長，多出來的布就**擠成細碎的小皺褶**，像揉過的紙（尤其袖子、腋下）。真的布有一點硬度，會形成幾條**大而平滑**的褶。

**做法：** 懲罰「每個頂點偏離鄰居平均位置」的量：

```
彎曲能量 ＝ bend × Σ (頂點 − 它所有鄰居的平均位置)²
```

- 細碎的皺褶 → 每個點都跟鄰居差很多 → 罰很重
- 平滑的大褶 → 每個點都接近鄰居的平均 → 罰很輕

這一項叫**拉普拉斯平滑**，它的矩陣不會隨迭代改變，所以一開始就加進矩陣（第 78～85 行）。

### 選項 3：重力（`gravity`）

每個頂點加一個往下的固定力（第 109 行）。**實驗結果是不好用**：沒有東西撐住衣服（縫合沒有摩擦），重力只會把布往下拉得更長，所以預設是 0。

## 7️⃣ 實驗結果（紅 T，4-bit）

| 設定 | 領口縫合後 | 拉長 >10% 的邊 | 結果 |
|---|---|---|---|
| 原本 | 99.1 cm | 10.9% | 肩膀被撐長 |
| 只加重力 0.02 | 138.6 cm | 44% | 布被拉得更長 |
| 只限制領口 | 78.7 cm | 16.6% | 拉長轉移到肩膀，胸口多一道凹痕 |
| 限制領口以外 | 75.5 cm | 1.0% | 領口自己就不被撐大 → **源頭是肩膀** |
| 限制整件 2%、權重 100 | 75.2 cm | 0.98% | 袖子擠出細碎皺褶 |
| **＋ 彎曲剛度 1** | **75.4 cm** | **1.21%** | **皺褶消失（採用）** |
| ＋ 彎曲剛度 5 | 76.8 cm | 3.24% | 太強，布反而被拉 |

**所有設定穿進身體的頂點都是 0%：不穿模和不拉長可以同時做到，是原本的權重選錯了。**

### 採用的設定（新流程）

```python
SEW = {"stretch_limit": 0.02, "stretch_weight": 100.0, "bend": 1.0}
```

### 副作用：衣服往上約 10 cm

- 舊設定：肩膀被撐開，衣服往下掛（肩膀比身體低 0.7 cm）
- 新設定：衣服正確地搭在肩上（肩膀比身體高 0.5 cm），整件往上 **9～10 cm**
- **布的長度沒變**（前中心 33.3 → 33.4 cm），只是掛的位置變高
- 舊設定其實**掩蓋了衣服太短**的問題；新設定讓它現形 → 由衣長校正處理（見 `筆記_衣長偏短問題與解法.md`）

## 8️⃣ 輸出與品質檢查

### 輸出：只換頂點位置

`write_obj_with_new_positions`（第 130～140 行）：複製原本的 OBJ，**只把 `v` 那幾行換成新位置**，UV（`vt`）、面（`f`）、材質都不動。

> 因為 UV 不變，**之後貼在版片上的顏色花紋會自動跟著縫好的衣服走**（見 `顏色花紋貼圖_做法.md`）。

### 品質指標（`quality`，第 143～161 行）

| 指標 | 意思 | 縫好的樣子 |
|---|---|---|
| 邊長偏離原始長度超過 10% | 布被拉長或壓短的比例 | 新設定約 1～2% |
| 最小角 < 10° 的三角形 | 細長的「橋」還有多少 | 縫合前約 7～9%，縫好後約 0% |
| 最長邊 | 最長的一條邊 | 縫合前 30～40 cm，縫好後約 2 cm |
| 在身體裡的頂點 | 穿模的比例 | 0% |
| 離身體距離（中位數） | 衣服多貼身 | 約 1.5～2 cm |

## 🔟 怎麼用

**單獨縫一件**（用預設＝舊設定）：

```bash
.venv\Scripts\python tools\chatgarment\sew.py output\chatgarment\<衣服資料夾> [身體.obj]
```

**在程式裡用新設定**：

```python
from sew import mesh_edges, rest_lengths, sew
edges = mesh_edges(faces)
rest = rest_lengths(vertices, edges, orig_lens)
x = sew(vertices, edges, rest, body=(身體頂點_公分, 身體面),
        stretch_limit=0.02, stretch_weight=100.0, bend=1.0)
```

**比較不同設定**：`tools/chatgarment/sew_experiment.py`（輸出比較表）、`tools/chatgarment/sew_variants.html`（網頁上並排看）

## ⚠️ 已知限制

| 問題 | 說明 |
|---|---|
| **正式流程還在用舊設定** | `to_design.py`、`export_for_physics.py` 呼叫 `sew.main()`，用的是預設值（沒有限制拉長）；只有實驗程式（`neck_general_mesh.py`、`hem_mesh.py`）用新設定 → 待接進正式流程 |
| **彎曲剛度會讓開口往內縮** | 開口邊緣（領口、下襬、袖口）的點只有一側有鄰居，「鄰居平均位置」偏向內側，所以會被往內拉。bend＝1 影響很小（領口 75.2 → 75.4 cm），bend＝5 就明顯。改進：開口邊緣的點不套用彎曲剛度 |
| **權重是「開或關」兩段** | 邊剛好在 2% 上下時，可能這輪變硬、下輪變軟，來回切換。目前結果穩定，先不處理 |
| **比較慢** | 碰到身體的點每輪不同，矩陣每輪都要重新分解；一件約 2～3 分鐘 |
| **不是物理** | 沒有重力和摩擦，多出來的布擠在哪就停在哪（例如腋下）。真正的垂墜交給紀泓宇的物理模擬 |
