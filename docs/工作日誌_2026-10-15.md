## 2️⃣ 翻領問題與修正

**原因：** ChatGarment 分兩次產生
1. 第一問：用文字描述衣服（例如 crew neck、短袖）→ 紅 T、白 T 都寫對了
2. 第二問：參考描述產生版型參數 → 領子配件（翻領、帽子、高領）在這一步選

兩步之間**沒有強制一致**，模型一個字一個字依機率產生，4-bit 的小誤差就可能讓它選到翻領。舊資料的 4-bit 和 bf16 比較，「領子配件」也是最常不一致的參數（10 件中 4 件）。

**修正：** `to_design.py` 以第一問的描述為準，修正第二問的領子配件（圓領／collarless → 無、hood → 帽子、turtle → 高領、notched／polo collar → 翻領）。三批結果共修正 6 件，網格重新生成後翻領消失。

**限制：** 第一問本身寫錯就救不了（例如格紋襯衫被描述成 collarless）。

## 3️⃣ 顏色貼到版片上

**做法：** 照片的顏色畫在版片的 UV 上，縫合、物理都只移動頂點、不動 UV，所以貼一次就會跟著衣服走。

```
商品照 → ① 去背（GrabCut）──┐
                             ├→ ③ 對齊 → ④ 烘焙進 UV 貼圖
衣服網格 → ② 平放（正面投影）─┘
```

**對齊試了兩種：**

| 方法 | 做法 | 結果 |
|---|---|---|
| TPS（預設） | 輪廓找 7 個特徵點（領口、袖口、下襬兩角、腋下），用薄板樣條把網格彎過去 | 紅領白 T 正面可用 |
| 方法 B：版片各自對齊 | 每片版片只能平移、縮放、旋轉，花紋不變形 | **失敗**，重疊率只有 0.47～0.64 |

**方法 B 失敗的原因：** AI 生成的衣服形狀跟照片差太多（太寬、太短），只能平移縮放就怎麼擺都對不滿。過程中也發現 GarmentCode 的 UV 長寬是分開縮放的，已用 box mesh 的邊長還原真實比例。

**未來方向（林宇鑫的想法）：** 讓版片自己去「看」照片 —— 把款式參數（衣長、寬鬆度、袖長）也當成可調的，反覆「畫成剪影 → 跟照片比較 → 調整參數」。這樣同時解決衣長偏短和貼圖對齊，等顏色流程學完再做。

## 4️⃣ 照紀泓宇的 SMPL-X 身體縫（暫緩）

**已完成：**
- 用 SMPL-X 權重檔自己算身體：`頂點 = v_template + shapedirs · betas`，betas 全 0 時跟紀泓宇給的 OBJ 每個頂點差 < 1e-6 m。之後他只要傳 `gender_model` ＋ `betas`
- 26 個打版尺寸的量測程式，用**比例校正**：GarmentCodeRC 沒附量測程式，所以用同一套幾何量法量「GarmentCode 的女性範本」和「目標身體」，目標尺寸 ＝ 範本尺寸 × 兩者比例
- 量法：每 0.5 cm 水平切一刀量凸包周長，依規則找胯下、臀、腰、腋下、脖子

| 驗證（紀泓宇的範例使用者） | 我們 | 紀泓宇 |
|---|---|---|
| 胸圍 | 86.7 | 86.04 |
| 腰圍 | 69.6 | 69.64 |
| 臀圍 | 91.9 | 91.87 |

**決定：** 目前先固定用紀泓宇給的 SMPL-X 平均女性（θ=0、betas 全 0），身體量測之後再處理。

## 5️⃣ 原版 bf16（RTX 3090）vs 4-bit（2026-10-16）

3090 那台是 Linux，安裝腳本是 Windows 用的，所以是手動架好環境跑的。結果帶回本機放在 `output/chatgarment_ai/bf16_3090/`（照片原檔名已改成 g 開頭的名稱）。黑 T、魚印花 T 是 `.webp`，`infer.py` 只吃 jpg／png，所以沒跑到，共比較 6 件。

| | 4-bit（RTX 5050） | bf16 原版（RTX 3090） |
|---|---|---|
| 每張時間 | 25～46 秒 | **13～16 秒** |
| 顯示卡記憶體峰值 | 約 5.9 GiB | 約 15.4 GiB（整個模型放進顯示卡） |
| 衣長（6 件平均） | 1.09 | **1.21** |
| 衣長換算（男性平均身材，頸到腰 38.3 cm） | 約 42 cm | 約 46 cm |

- 參數一致率 56／72（78%），76 個正規化數值平均差 0.034（報告：`report_4bit_v2_vs_bf16_3090.md`）
- **衣長：** bf16 每件都比 4-bit 長約 0.12（約 4.6 cm），跟舊照片的結果一致。但 bf16 的 1.19～1.24 還是只到腰下一點，一般 T 恤下襬在臀部約要 1.6 → **換成原版也解決不了偏短，還是要校正**
- **袖長：** 長袖（兩件帽 T、米色長袖）bf16 比較長，比較接近照片
- **bf16 自己的錯：**
  - 紅 T、灰條紋 T 的領型變成方領（照片是圓領）
  - 白 T 的類型變成合身款（FittedShirt）、領型變成弧形領
  - 紅 T 袖長只有 0.16，比照片短很多
  - 紅 T、灰條紋 T、白 T 也多了高領配件 → 被 `fix_collar` 修掉

**結論：** 原版不是全面比較好。它的衣長、長袖比較準，但領型會出錯；4-bit 的領型反而比較穩。兩種都需要「描述 vs 參數一致性檢查」和「尺寸校正」。
