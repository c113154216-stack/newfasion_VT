## 需要一起決定的

### 3. 畫面放在哪一頁
你的姿態頁跟我的 Three.js 試穿畫面，要做在**同一頁**還是**分開兩頁**？
- **同一頁（我建議）：** 姿態封包不用跨頁傳，延遲最少；Webcam 畫面不顯示，只當輸入（§1.3）。
- **分開：** 要多一層傳輸（WebSocket 等），會吃掉一些 8～13 ms 的預算。

### 4. 資料怎麼流到畫面
我這邊每幀需要兩樣東西：**身體頂點**和**衣服頂點**。這兩樣都是紀泓宇算的，但要經過誰轉送？
- 姿態封包 → 紀泓宇的程式（在哪裡跑？瀏覽器、Python 後端？）→ 畫面
- 如果紀泓宇的程式在 Python 後端，就要決定瀏覽器和後端之間怎麼傳，例如 WebSocket 二進位。
  - 由誰架這個後端？是你原本的 Flask 嗎？

### 5. 生成好的衣服網格放哪、怎麼對應商品
我建議這樣：
```
商品上架 → 你的後端存照片和尺寸表 → 呼叫我的生成程式（離線、先算好）
→ 輸出 garments/<product_id>/<product_id>.obj ＋ _pins.json
→ 使用者選商品時，畫面依 product_id 載入
```
要確認的：
- 資料夾位置和命名，還是要存進資料庫（存路徑就好）？
- 上架時誰觸發生成？生成要有 GPU，而且一件要數十秒，要不要做成背景工作？

### 6. 使用者輸入身材的地方
- 身高、體重、胸圍、腰圍、臀圍這五項的輸入介面由誰做？放在哪一頁？
- 輸入框旁邊的「怎麼量」說明文字，要跟紀泓宇的量測定義一致（他的清單 A-4）。

### 7. 尺寸推薦的交接
