## 1️⃣ 抓論文程式碼

### 做法
三個 repo 都抓到 `third_party/`，並 **checkout 到固定的 commit**。作者之後改程式，我們這邊也不會跟著壞掉。

| Repo | 固定的 commit |
|---|---|
| ChatGarment | `798c34ac04319668aaa0e3a3a02d44284fbd70ec` |
| GarmentCodeRC | `e3d4476d6f9bcb0af5ee0eccd18b0433e3df398a` |
| DeepBump | `fad19ba87daed12b1d0410a57e74f3d79e82f78d` |

### 為什麼用 GarmentCodeRC，不用原版 GarmentCode
ChatGarment 的作者自己改了一版 GarmentCode，也就是 GarmentCodeRC。ChatGarment 輸出的款式參數格式是對應這一版的，用原版會對不上。

### ChatGarment 要的 assets 連結
作者 README 要求 `ChatGarment/assets` 指向 `GarmentCodeRC/assets`。
Windows 上用 **junction** 做連結（`mklink /J`），不需要系統管理員權限。

## 2️⃣ 下載 ChatGarment 權重（14 GB）

| 項目 | 內容 |
|---|---|
| 檔案 | `pytorch_model.bin` |
| 放在 | `third_party/ChatGarment/checkpoints/try_7b_lr1e_4_v3_garmentcontrol_4h100_v4_final/` |
| 來源 | 作者 README 的 Pretrained weights 連結（SharePoint） |

> 🐛 **踩過的坑：瀏覽器下載一直卡住**
> - SharePoint 的大檔案用瀏覽器下載，中途會停住，而且不能續傳
> - **解法**：從 SharePoint 的 API 取得檔案的直接下載網址（`@content.downloadUrl`），改用 `curl` 下載，斷掉可以續傳
> - 下載完比對檔案的 CRC 檢查碼，確認檔案完整沒壞

## 3️⃣ Python 環境：分成兩個

| 環境 | 用途 | 裝什麼 |
|---|---|---|
| `.venv` | 打版、縫合、預覽圖、貼圖、法線貼圖 | `tools/chatgarment/requirements.txt` |
| `.venv-chatgarment` | ChatGarment 推論、SMPL-X | `tools/chatgarment/requirements-ai.txt`（約 3～4 GB） |

> 💡 **為什麼要分開**：ChatGarment 要的 transformers 4.37.2 和 GarmentCode 要的套件版本互相衝突（例如 numpy），放同一個環境一定有一邊壞掉。

### 一定要鎖住的版本

| 套件 | 版本 | 原因 |
|---|---|---|
| libigl | **2.5.1** | 2.6 起 `facet_components` 的回傳格式改了，GarmentCodeRC 會出錯 |
| numpy（`.venv`） | **1.26.4** | GarmentCode 要 numpy < 2 |
| opencv-python-headless | **4.10.0.84** | 4.12 起會把 numpy 升到 2.x，GarmentCode 就壞了 |
| transformers | **4.37.2** | ChatGarment 的模型程式依賴這個版本的內部寫法 |
| torch | **2.11.0+cu128** | RTX 50 系列需要 CUDA 12.8；作者原本指定的 torch 2.1.2 不支援這張卡 |
| bitsandbytes | 0.50.2 | 4-bit 量化（NF4），讓 8 GB 顯示卡跑得動 |

> 📝 torch 要從 PyTorch 自己的套件庫抓：`--extra-index-url https://download.pytorch.org/whl/cu128`，已經寫在 requirements 裡。

## 4️⃣ 讓 8 GB 顯示卡跑 14 GB 的模型

原版 ChatGarment 是 bf16，光權重就約 14 GB，RTX 5050 只有 8 GB 放不下。

**做法：自己寫載入程式（`tools/chatgarment/infer.py`），把大部分層壓成 4-bit**
- 224 個線性層改成 **NF4 4-bit**（每 64 個數一組，各存一個縮放值）
- 看圖的 CLIP、投影層、輸出層等**保留 bf16**，避免精度掉太多
- 權重用 memory-map 讀，邊讀邊量化，不用一次把 14 GB 載進記憶體

| 模式 | 什麼時候用 | 速度 |
|---|---|---|
| `auto`（預設） | 顯示卡 ≥ 20 GB → bf16，否則 → 4-bit | — |
| 4-bit | RTX 5050 | 約 25 秒／張 |
| bf16 | RTX 3090（24 GB），原版精度 | 預計每張數十秒 |
| bf16 分流到記憶體 | 8 GB 卡硬跑原版，要加 `--confirm-bf16` | 將近 1 小時／張 |

## 5️⃣ 寫成程式：一鍵安裝＋一鍵檢查

> 💡 原則：**所有安裝步驟都寫在程式裡**，換電腦照著跑就好，不靠記憶打指令。

### 一鍵安裝：`tools/setup/setup.ps1`
在 `newfashion_VT` 根目錄開 PowerShell：
```powershell
powershell -ExecutionPolicy Bypass -File tools\setup\setup.ps1
```
已經做過的步驟會跳過，可以重複執行。它會：
1. 抓三個 repo 到 `third_party/`，checkout 到固定 commit
2. 建 assets 的 junction 連結
3. 建 `.venv` 並安裝套件
4. 建 `.venv-chatgarment` 並安裝套件
5. 檢查 ChatGarment 權重、SMPL-X 權重有沒有放好，缺的話告訴你去哪拿

### 一鍵檢查：`tools/setup/check_env.py`
先檢查 6 個檔案有沒有到位：兩份原始碼、assets 連結、DeepBump 模型、ChatGarment 權重、SMPL-X 權重。再跑 7 項環境測試：

| # | 檢查 | 環境 |
|---|---|---|
| 1 | GarmentCode 套件版本（libigl、numpy 有沒有被升級） | `.venv` |
| 2 | DeepBump 執行環境（onnxruntime） | `.venv` |
| 3 | GarmentCode 能不能打版 | `.venv` |
| 4 | PyTorch 抓不抓得到顯示卡 | `.venv-chatgarment` |
| 5 | 4-bit 量化（bitsandbytes NF4）能不能用 | `.venv-chatgarment` |
| 6 | ChatGarment 模型程式能不能載入 | `.venv-chatgarment` |
| 7 | SMPL-X 能不能產生人體 | `.venv-chatgarment` |

目前全部 ✔。

### VS Code 不用打指令
`.vscode/launch.json` 把每個步驟都設好，**按 `Ctrl+Shift+D` → 選一項 → 按 ▶**：

| 選單項目 | 做什麼 |
|---|---|
| 0 檢查環境 | 跑 `check_env.py` |
| ① AI 判斷款式 | ChatGarment 推論（自動選 4-bit／bf16） |
| ② 生成網格並縫合 | 款式 → 版片 → 縫合 |
| ③ 輸出給物理 | T-pose、公尺、固定點 |
| ④ 顏色貼圖 | 照片貼到版片上 |
| ⑤ 打包衣服網格給隊友 | 產生 zip |
| 網格檢視網站／3D 檢視頁 | 開本機網頁伺服器 |

每一項都已經指定好用哪個環境，不用自己切換。

## 🐛 其他踩過的坑

| 問題 | 原因 | 解法 |
|---|---|---|
| `setup.ps1` 執行時中文變亂碼、跑不起來 | Windows PowerShell 5.1 預設不是用 UTF-8 讀檔 | 檔案存成 **UTF-8 BOM** |
| `.sh` 腳本在 Linux 上跑不了 | Windows 把換行改成 CRLF | `.gitattributes` 設 `*.sh text eol=lf` |
| GarmentCode 低解析度時當掉 | 它印警告時用到 `Edge` 沒有的 `name` 屬性 | 在我們的程式裡補一個預設值，不改第三方程式碼 |
| `robocopy` 回報錯誤碼 1 | 它的 1 代表「有複製檔案」，不是失敗 | 判斷時把 0、1 都當成功 |
