# 📄 論文筆記：OmniFabric（衣服貼圖：照片 → 版片 UV 上的顏色花紋）

> 💡 **一句話**：給一張衣服照片，先用 ChatGarment 做出版片和 3D 衣服，再把照片的顏色花紋「搬」到版片的 UV 上（粗貼圖），最後用一個 DiT（擴散 Transformer）＋LoRA 把粗貼圖**整理乾淨**：拉正變形、去掉烤進去的影子和皺褶、讓分開的版片接縫連續。輸出的是**乾淨的版片貼圖**，可以拿去做物理模擬和重新打光。
> 📅 整理日期：2026-11-10

## 1️⃣ 要解決的問題

- 從一張照片做「能用的」3D 衣服，貼圖常見兩個問題：
  - **把環境光、影子直接烤進貼圖**：之後放進物理模擬或換燈光，影子還黏在布上。
  - **整體不連貫**：例如 FabricDiffusion 只抽一小塊「可重複拼貼」的布紋，**不對稱的圖案、大印花、logo 做不出來**。
- OmniFabric 的做法：直接在**版片的 2D UV 空間**產生整件衣服的貼圖，而不是只做一小塊布紋。

### 論文列的 4 個貢獻

1. 從單張照片產生高品質、整體連貫的衣服貼圖的方法。
2. **自動資料工廠**：大量產生「有貼圖的版片」當訓練資料。
3. 用一個**標準姿勢的 3D 網格當橋樑**，把照片的像素對應到版片 UV。
4. **先粗後細**：先做出位置大致對的粗貼圖，再用 DiT 修掉變形和烤進去的光影。

## 2️⃣ 方法：6 個步驟

```
照片 → ① ChatGarment 版片＋縫好的衣服 → ② UV 模板、3D 位置圖、灰色衣服的正面渲染
→ ③ 把照片的花紋「畫」到灰色衣服正面 → ④ 產生 360° 多視角 → 投影回 3D
→ ⑤ 烤到版片 UV（粗貼圖 T′）→ ⑥ DiT＋LoRA 整理成乾淨貼圖 T
```

| 步驟 | 做什麼 | 用的模型 | 輸出 |
|---|---|---|---|
| ① 版片 | 照片 → 版片 → 縫好、穿在 **A-pose** 的 SMPL 身體上 | ChatGarment、GarmentCode | 版片 P、網格 M_R |
| ② 準備 | 版片 UV 模板；**3D 位置圖 P_pos**＝把每個 UV 像素對應的 3D 座標（xyz）存成一張圖；渲染灰色衣服的正面 | — | `position_map.pt` |
| ③ 正面上色 | 把照片裡的衣服花紋「轉」到灰色衣服的正面渲染上（姿勢、輪廓照灰色衣服，顏色花紋照照片） | 論文：Nano Banana Pro（Gemini）；程式也可選 **FLUX.2-dev**（全自動） | 正面渲染 R_f |
| ④ 多視角 | 以 R_f 產生衣服轉一圈的影片，取前、後、左、右 4 個視角，投影回 3D 網格 | 論文：Veo 3；程式：MiniMax-H3-360（ComfyUI）或 FLUX.2 | 4 個視角 |
| ⑤ 粗貼圖 | 投影結果烤到版片 UV。先投前、後，左右只補還沒上色的地方；同一個部位的版片（例如袖子前後片）排在一起，花紋才連續 | — | `coarse_texture.png`（T′） |
| ⑥ 整理 | **DiT＋LoRA**：輸入 T′、R_f、P_pos，輸出乾淨貼圖 T；再放大解析度 | DiT（照 OminiControl 的多條件做法）＋ LoRA；超解析度（程式用 Real-ESRGAN） | `normalized_texture.png`（T） |

### 🔑 關鍵設計：3D 位置圖 P_pos

- 版片在 UV 上是**一塊一塊分開的**（前片、後片、袖子…），只看 2D 的話，網路不知道「前片右邊緣」和「袖子左邊緣」在 3D 上是接在一起的。
- P_pos 把每個 UV 像素標上它在 3D 的位置，網路就能學到**版片之間怎麼接**，接縫處的花紋才會連續。
- 位置編碼：T′、P_pos、T 在同一個位置的小塊用**相同的編碼**（對齊）；R_f 是另一張圖，用自己的座標。全部的條件和要去雜訊的 token 一起做 self-attention。

### 背面怎麼來

- 只靠第 ④ 步的 360° 影片模型「推測」背面，**沒有另外處理背面的模組**。
- 👉 我們的 3090 版改成：**有背面照就用背面照上色**（同一個 FLUX.2 步驟、提示詞改成背面），沒有才讓模型推測。

### 影子、皺褶怎麼去掉

- **不是用物理去算**，是讓網路從資料學：訓練資料每件衣服用不同的隨機種子模擬（皺褶不同）、隨機打白色點光源（影子不同），網路學「有雜訊的 T′ → 乾淨的 T」。
- 論文附錄自己承認：還沒有嚴格地把固有色（albedo）和光影分開。

## 3️⃣ 訓練資料（自動資料工廠）

| 項目 | 內容 |
|---|---|
| 衣服 | GarmentCodeData 挑 **3,000 件**不同款式 |
| 貼圖 | 拿 DeepFashion 的照片當參考 → LLM（Qwen）寫出貼圖的描述（圖案位置、元素、配色）→ Gemini 依描述＋參考圖產生貼圖。目標是「合理、真實」，不是複製參考圖 |
| 數量 | **30,000 組**有貼圖的版片（每款平均 10 種貼圖） |
| 模擬 | NVIDIA Warp，每組隨機種子；隨機白色點光源 |
| 一組訓練資料 | (T′, R_f, P_pos, T)：粗貼圖、正面渲染、位置圖、正確答案 |
| 變形增強 | 對正確貼圖做隨機**薄板樣條（TPS）變形**再去模擬，未變形的當答案 → 網路學會把變形拉回來 |
| 切分 | 測試：訓練 ＝ 0.1 |
| LoRA 訓練 | 單張 **A6000**、batch 8、VAE 和 DiT 主體凍結、版片圖縮放＋補邊到 **1024×1024**、訓練到收斂。loss 是一般的擴散去雜訊 MSE |
| 沒寫的 | LoRA rank、學習率、訓練步數、訓練時間 |

## 4️⃣ 實驗結果

**比較對象：** FabricDiffusion、Paint3D、Hunyuan3D-2.0（都給同樣的正面渲染 R_f 和網格，結果投回 UV 比較）。

### 合成測試集（有正確答案）

| 方法 | LPIPS ↓ | SSIM ↑ | MS-SSIM ↑ | DISTS ↓ | CLIP-s ↑ |
|---|---|---|---|---|---|
| FabricDiffusion | 0.273 | 0.645 | 0.707 | 0.259 | 0.906 |
| Paint3D | 0.311 | 0.657 | 0.704 | 0.266 | 0.890 |
| Hunyuan3D-2.0 | 0.223 | 0.712 | 0.717 | 0.220 | 0.924 |
| **OmniFabric** | **0.092** | **0.868** | **0.905** | **0.121** | **0.963** |

### 使用者評分（13 人、10 張真實照片）

| 方法 | 整體排名 ↓（1～4） | 像不像照片 ↑ | 背面合理 ↑ | 整體連貫 ↑（1～5） |
|---|---|---|---|---|
| FabricDiffusion | 3.40 | 1.75 | 2.69 | 3.15 |
| Paint3D | 3.41 | 1.86 | 2.81 | 3.03 |
| Hunyuan3D-2.0 | 2.10 | 3.43 | 3.41 | 3.50 |
| **OmniFabric** | **1.09** | **4.44** | **4.35** | **4.41** |

### 全開源版本（我們 3090 能用的）

把 Gemini／Veo 換成 FLUX.2（＋Ministral 3 改寫提示詞）：

| | LPIPS ↓ | SSIM ↑ | DISTS ↓ | CLIP-s ↑ |
|---|---|---|---|---|
| 原版 | 0.092 | 0.868 | 0.121 | 0.963 |
| 全開源 | 0.114 | 0.847 | 0.149 | 0.955 |

👉 稍微差一點，但還是比所有比較對象好很多。

### 消融（拿掉哪個條件影響最大）

| | LPIPS ↓ | SSIM ↑ |
|---|---|---|
| 完整 | 0.092 | 0.868 |
| 拿掉粗貼圖 T′ | **0.407** | **0.601** |
| 拿掉正面渲染 R_f | 0.097 | 0.850 |
| 拿掉位置圖 P_pos | 0.098 | 0.848 |

👉 **粗貼圖是最重要的輸入**；R_f、P_pos 各自幫一點。第 ⑥ 步整理之後，LPIPS 從 0.144 降到 0.092，修掉了前面步驟累積的誤差。

## 5️⃣ 限制（論文自己寫的）

- 多視角產生錯了，貼圖就會對不上。
- **ChatGarment 的版型錯誤它修不了**（只管貼圖，不管形狀）。
- 看不到、被擋住的地方會「腦補」。
- 皮革、金屬這種反光很強的布料做不好。
- 只輸出顏色貼圖，**沒有**粗糙度、金屬度、法線圖。
- 固有色和光影沒有嚴格分開。

**硬體：** 作者在 A6000（48 GB）上測；一件約 5 分鐘（用 Gemini 時看伺服器負載）；模型約 200 GB（FLUX.2-dev 就 110 GB）。FLUX 是非商用授權，專題可用；MiniMax-H3 的授權不含美國等地區，用 FLUX.2 可以避開。

## 6️⃣ 對我們專題的意義

| | OmniFabric 原本 | 我們的情況 | 要處理的 |
|---|---|---|---|
| 版片 | ChatGarment 直接輸出 | 一樣是 ChatGarment，但我們有**校正**（領深、衣長、袖長、領口形狀…） | 它的版片和我們校正後的版片**尺寸不同** → 貼圖要照每片版片縮放、對位 |
| 姿勢 | A-pose＋重力 | T-pose、無重力（SMPL-X 中性） | 貼圖在 UV 上，跟姿勢無關，影響小 |
| 背面 | 模型推測 | 我們有真的背面照 | ✅ 3090 版已改成用背面照 |
| 顯示卡 | 48 GB | 3090（24 GB） | ✅ 已改成分段載入、分層搬運（`tools/omnifabric_3090/`），**試跑中** |
| 法線圖 | 沒有 | 畫面要布紋質感 | 另外加布料法線圖 |

**目前計畫：** 68 件先用「主色＋布料法線圖」全部上色；**有花紋、印花的**再用 OmniFabric。等 3090 試跑 h05 的結果出來，再看貼圖品質和每件花的時間。
